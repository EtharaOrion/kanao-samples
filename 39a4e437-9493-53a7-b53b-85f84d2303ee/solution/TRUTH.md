# Ground truth: multiphase-cicd-carry

The trusted engine at /usr/local/lib/cicd/engine.js threads a five phase pipeline (lint, build, test, package, publish) onto one accumulating carry, where every record names the number of earlier phases it inherited through its carried count, so a healthy carry has the record at index i reporting a carried count of exactly i and a digest that chains from its predecessor. The engine is immutable and correct; it refuses to invent a carry it did not thread, so any hand written or fabricated carry fails cicd verify and the report never declares such a carry complete.

The planted fault lives entirely in the workspace driver at /workspace/bin/run-pipeline. It threads lint, build, and test onto the accumulating carry correctly, then during a simulated incident window it isolates the package phase by folding the accumulated carry down to the test tip with cicd fold --carry carry.json --into stage.json --keep 1, threading the package phase against that single record stage, and copying the truncated stage carry back over the pipeline carry. This collapses lint and build out of the recorded history: package and publish are threaded against a carry that no longer holds the earlier phases, so the final carry reports collapsed carried counts and the engine report declares the pipeline incomplete even though all five phases ran. This is a long horizon state collapse in the sense of archetype AR1, because the earlier accumulated state is silently discarded by a later phase and the failure only surfaces at the end of the horizon.

The repair threads every phase against the single accumulating carry, removing the fold and the copy back, so the package phase runs on the complete history and the engine threads five records end to end with carried counts 0 through 4 and a report that declares the pipeline complete with carried_final four. The reference solution at solution/solve.sh rewrites the driver to thread all five phases against one carry and then runs cicd verify to confirm the chain. A solver that fabricates a five record carry or a complete report directly instead of threading it through the engine is caught by the fabricated report detector, which reads a carry that has five or more records but does not recompute under the chain and carried invariants.
